# Vibe Coding Skill

## 目标
在保持项目可运行的前提下，以快速迭代和高反馈密度的方式完成功能开发。

## 适用场景
- 需要快速验证想法或交互原型
- 需求还在探索，期望先跑通主链路
- 希望通过小步提交持续获得可见成果

## 工作原则
1. **先跑通，再精修**：优先打通端到端流程，再补充边界处理。
2. **小步快跑**：每次只改一个明确点，保持改动可回退、可解释。
3. **高频反馈**：每轮改动后立即运行对应检查（lint / test / build）。
4. **最小改动面**：只修改与当前目标直接相关的文件和逻辑。
5. **可读优先**：命名清晰、结构直观，避免“聪明但难懂”的实现。

## 标准流程
1. 明确本轮目标与验收标准（可观察、可验证）。
2. 定位最小改动路径并实施。
3. 运行相关校验并记录结果。
4. 根据反馈做下一轮微调。
5. 在满足验收后再做必要重构与文档补充。

## 输出要求
- 提交内容应聚焦单一目标。
- 描述需说明“做了什么、为什么这样做、如何验证”。
- 若有已知限制，明确列出后续处理建议。

## 质量门槛
- 不引入新的 lint 错误。
- 不降低既有测试通过率。
- 不破坏现有构建流程。
- 不引入明显安全风险（例如：对外部输入做白名单/长度校验，不提交 API Key、Token、密码等敏感信息）。
